## Supabase — נדרשת גישה לפרויקט הקיים

תוסף Supabase אינו מותקן/מחובר בחשבון השיחה לפי הבדיקה האחרונה. בעותק המקומי נמצא רק `app/config/example.json`, ללא פרטי חיבור אמיתיים לקובץ פיתוח.

כדי לעבוד מול הדיבי הקיים:

1. החבר מזמין את חשבון Supabase של המשתמש לארגון שבו נמצא הפרויקט. תפקיד Developer מתאים לעבודה על תוכן הדיבי. שינוי הגדרות פרויקט או Auth עשוי לדרוש פעולה של Administrator/Owner.
2. המשתמש מאשר את ההזמנה ומתקין ומחבר את תוסף Supabase באמצעות החשבון שלו.
3. מקבלים את כתובת הפרויקט ואת מפתח ה־Publishable עבור הגדרות האפליקציה. אלה מוכנסים לקובץ הפיתוח המוחרג מגיט, לפי התבנית הקיימת.
4. עם הגישה, בודקים את הפרויקט ואת המיגרציות שכבר הוחלו לפני תכנון השינויים. שומרים על תהליך המיגרציות של המאגר ועל החיבורים הקיימים.

בחבילות Free/Pro ההרשאה היא ברמת הארגון; הרשאה מוגבלת לפרויקט זמינה ב־Team/Enterprise. ראו [הרשאות Supabase](https://supabase.com/docs/guides/platform/access-control).

## Figma — אופציונלי למימוש, שימושי לעיצוב משותף

תוסף Figma אינו מותקן/מחובר לפי הבדיקה האחרונה. אפשר להמשיך בהמחשות מקומיות ובפיתוח Flutter גם בלעדיו.

אם רוצים עיצובים שאפשר לערוך ולשתף ב־Figma:

1. מתקינים ומחברים את תוסף Figma לחשבון המשתמש.
2. אם יש קובץ עיצוב קיים של החבר, נותנים לחשבון המשתמש גישת עריכה ומשתפים קישור אליו.
3. אם אין קובץ קיים, אפשר ליצור קובץ עיצוב חדש לאחר החיבור; אין צורך להמציא קישור או להניח שכבר קיים קובץ.

## סביבת בדיקות ופלטפורמות נוספות

- Android SDK אינו מותקן לפי `flutter doctor`. הוא דרוש לפני בנייה או בדיקה במכשיר Android, אך אינו חוסם עבודה במחשב וב־iOS.
- לא נמצאו `psql`, `initdb` או Docker ב־PATH. יש להקים סביבת PostgreSQL מקומית לפני הרצת חבילת בדיקות SQL המקומית הקיימת; זו עבודת הכנה שניתן לבצע בנפרד מחיבור לחשבון החבר.
- בבדיקה זו לא בוצעה בנייה חדשה לאייפון, ולא הורצו בדיקות Flutter או SQL. זמינות הכלים אינה אישור לכך שכל תהליך האפליקציה עובד.
- גישה ל־Google Cloud אינה דרישה מיידית לעיצוב. נבדוק את הצורך אם יהיה צורך לשנות הגדרות OAuth של החיבור הקיים.

## העבודה שאפשר להתחיל כעת

עיצוב המסכים המלאים בסגנון שסוכם ומימוש מקומי שלהם באמצעות נתוני הדגמה. את חיבור התהליכים החדשים לדיבי הקיים ואת הבדיקה מולו משלימים לאחר מתן הגישה. החלטות מוצר שנותרו פתוחות מסומנות בטיוטת האפיון, ואין לראות בהן החלטות סופיות.
